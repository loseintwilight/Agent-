# 快速理解最近爆火的 AI 名词：从 LLM 到 Loop Engineering，一篇搞定不懵圈

> 一篇写给 AI 小白的「名词速查地图」：搞懂每个词在解决什么问题，比背定义重要得多。

---

## 前言

最近和同学聊天，越来越多人吐槽：**AI 圈的词更新得太快了**。

LLM、RAG、Agent 还没搞明白，又冒出来 Skill、CLI、Tool、Harness、MCP；好不容易把这些捋顺，2026 年又开始铺天盖地聊 Loop Engineering……

> 很多同学不是不想学 AI，是**一打开技术文章就被名词劝退**。

这篇文章我把这些年最常出现、面试和项目里最高频的 AI 名词，**按"基础入门 → 工程应用 → 2026 最新爆火"分成三大类**，每类按时间线排序。全程大白话，不堆公式、不深挖原理，**看完你能跟人聊明白每个词是干啥的、解决了什么问题**。

建议收藏，刷到陌生名词随时回来翻。

---

## 一、基础入门篇：看懂 AI 文章的必备词汇

> 这是所有 AI 内容的底层词汇，最早进入大众视野，也是理解后面所有概念的前提。

### 1. LLM（大语言模型）

**大白话：AI 的「大脑本体」**

你可以把它当成一个读遍了全网书籍、文章、代码的超级学霸，核心能力只有一件事——**根据上文，预测下一个字该说什么**。

它本身不会上网、不会操作软件、不会主动干活，只能输出文字。我们常用的 ChatGPT、豆包、通义千问、文心一言，背后都是不同的 LLM。

```text
一句话记住：LLM = 会说话的大脑，只动嘴，不动手。
```

### 2. Token（令牌）

**大白话：AI 的「认字单位 + 计费单位」**

AI 不是一个字一个字读内容的，它会把文字切成一小块一小块来处理，这一小块就是 Token。比如 "人工智能" 在中文里可能是 1-2 个 Token，一个长英文单词可能拆成 2-3 个 Token。

我们买 API 额度、聊上下文大小，说的都是 Token。粗略估算：

```text
1000 个汉字 ≈ 700 个 Token
1 个英文字母 ≈ 0.25 个 Token
```

### 3. Prompt（提示词）

**大白话：你发给 AI 的所有内容**

你在输入框里敲的问题、指令、附上的资料、代码片段……**只要是喂给 AI 的内容，全都叫 Prompt**。

Prompt 是你和 AI 沟通的"原材料"，原材料越清晰，AI 输出的质量越高。

### 4. Prompt Engineering（提示工程）

**大白话：「怎么跟 AI 说话才能让它干对活」的学问**

同样一件事，有人说出来 AI 输出一堆废话，有人说出来 AI 直接产出可用结果——**这中间的差距就是提示工程**。

比如给 AI 设定角色、规定输出格式、附上参考例子（Few-shot）、划清边界，都是提示工程的技巧。这是 2023 年最火的 AI 技能，**现在已经是 AI 使用者的基础操作**。

### 5. Hallucination（幻觉）

**大白话：AI 一本正经地胡说八道**

LLM 的本质是"猜下一个字"，它没有"对错"的概念。遇到不会的问题，它**不会说"我不知道"，而是会编出一套听起来很像真的答案**。人名、数据、代码、API、知识点，全都能编。

这是所有大模型的通病，也是后面 RAG、知识库、事实性校验这些技术存在的根本原因。

### 6. Context Window（上下文窗口）

**大白话：AI 的「短期记忆力上限」**

你和 AI 对话时，它能**同时记住的所有内容总长度**，就是上下文窗口。

- 窗口越大，你一次能喂给它的资料越多
- 窗口越大，它能记住的对话轮次越长
- 窗口太小，聊多了它就会"失忆"，忘了前面说过的要求

> 早期 GPT-3 只有 4K Token，现在主流模型已经做到 128K、200K、1M，**这个数字直接决定了你能不能把整本电子书丢给 AI**。

## 二、工程应用篇：做 AI 项目必接触的术语

> 这部分是真正做 AI 开发、搭项目时会高频遇到的概念，从早期的微调、RAG，到后来的 Agent、工具生态，按技术普及的时间线排列。

### 1. Fine-tuning（微调）& SFT（有监督微调）

**大白话：给 AI 大脑「定向补课」**

用你自己的一批数据，对现成的大模型再训练一会儿，让它的**说话风格、回答格式、专业知识**更贴合你的需求。

其中 SFT（有监督微调）是最常见的微调方式：给模型喂大量"问题 → 标准答案"的配对数据，让它学会按人类想要的方式回答。

### 2. LoRA（低秩适配）

**大白话：低成本微调技术，不用动整个大脑**

全量微调要修改模型的全部参数，贵到普通团队根本用不起。**LoRA 只额外训练一小部分参数，原模型一动不动**，效果却接近全量微调，成本只有几十分之一。

现在个人、小团队做微调，**基本都用 LoRA**。

### 3. Embedding（向量嵌入）

**大白话：把文字变成一串数字，让计算机能"算相似度"**

人类能看懂"苹果"和"水果"意思接近，但计算机只认数字。Embedding 就是把一句话、一段文字转换成一长串数字（向量），**意思越相近的文字，对应的数字就越接近**。

这是 RAG、语义搜索、推荐系统的核心基础。

### 4. 向量数据库

**大白话：专门存「数字向量」的数据库**

MySQL 存表格文字，向量数据库专门存 Embedding 生成的数字串。它最擅长的事：**给你一句话，快速从几百万条资料里找出意思最相关的那几条**。

常见的有 Chroma、Milvus、Qdrant、Pinecone。

### 5. RAG（检索增强生成）

**大白话：给 AI 配一个「外挂知识库」**

LLM 的知识是训练时截止的，也不知道你的私有资料。RAG 就是解决这个问题的：

```text
1. 先把你的文档、项目资料切成小块，存进向量库
2. 你提问时，先从库里搜出最相关的内容
3. 再把"问题 + 资料"一起塞给 LLM，让它照着资料回答
```

这样既能答私有内容，又能大幅减少胡说八道。

> 通俗比喻：**开卷考试**。LLM 闭卷答题，RAG 给它翻参考书。

### 6. Tool（工具调用 / Function Call）

**大白话：给 AI 装的「外部能力插件」**

纯 LLM 只会聊天，不会算复杂数学、不会搜最新新闻、不会读你本地文件。接上 Tool 之后，它就能**自己调用计算器、搜索引擎、文件系统、数据库、第三方 API**，来完成更复杂的任务。

我们常说的 Function Call，就是实现工具调用的主流方式。

### 7. SSE（服务器推送事件）

**大白话：让 AI 回答「逐字蹦出来」的技术**

你用 ChatGPT 时，回答不是一下子全显示，而是像打字一样逐个字出来，这就是 SSE。它是一种轻量的流式传输技术，**不用等 AI 全部算完再显示，边算边输出，体验好很多**。

```javascript
// SSE 前端接收示例
const eventSource = new EventSource('/api/chat');
eventSource.onmessage = (event) => {
  document.getElementById('output').innerText += event.data;
};
```

### 8. CLI（命令行工具）

**大白话：敲命令就能用的 AI 工具，不用点图形界面**

对于开发者来说，很多 AI 工具没有可视化窗口，**直接在终端敲几行命令就能调用大模型、启动 Agent、连接工具、部署服务**，这就是 CLI 工具。

它的好处是**快、容易自动化**，适合写脚本批量跑任务。

### 9. Agent（智能体）

**大白话：从「只会动嘴的顾问」变成「会动手干活的员工」**

以前的 LLM 只能输出文字。Agent 不一样，你给它一个目标，**它能自己规划步骤、调用工具、执行操作、出错了自己调整，直到把事情做完给你结果**。

比如你让 Agent "帮我分析这个 Excel 并写份报告"，它会**自己读文件、算数据、写文档**，全程不用你一步步指挥。

### 10. Skill（AI 技能包）

**大白话：给 Agent 提前封装好的「专用能力模块」**

不用每次都给 Agent 写一大堆提示词教它怎么干活，**Skill 就是把某一项能力（比如写前端页面、做数据分析、排查代码 bug）提前封装好，加载进去就能直接用**。

你本地的各种 skill 文件夹，本质就是一个个可复用的 AI 技能包。

### 11. Harness（运行 / 测试框架）

**大白话：套在 AI 外面的「标准化运行外壳」**

就像给手机装个通用手机壳，既能保护内部，又能统一接口。Harness 套在大模型或 Agent 外面，**统一管理输入输出、错误重试、结果校验、日志记录**，不用每次做项目都重复造轮子。

常见的有：

- **测试 Harness**：批量测 AI 回答准不准
- **运行 Harness**：给 Agent 提供稳定运行环境

### 12. MCP（模型上下文协议）

**大白话：AI Agent 的「通用插排」**

以前每个 Agent 想用工具，都得单独写对接代码。MCP 是一套统一标准，**相当于给所有 Agent 做了个通用 USB 接口**。

只要符合 MCP 规范，数据库、浏览器、文件系统、代码执行器等各种工具都能即插即用，Agent 随手就能调用。

它是 2025 年底到 2026 年爆火的协议，被称为 **Agent 时代的通用接口标准**。

### 13. Vibe Coding（氛围编程）

**大白话：不用抠细节，靠「描述感觉」让 AI 写代码**

以前写代码你得说清楚用什么框架、函数名、参数、返回值。Vibe Coding 就是你**只说大概感觉和目标**：

> "帮我做个暗黑科技风的个人主页，带 3D 粒子背景和滚动动画"

AI 自己把所有技术细节补上。

这个词火起来，是因为现在 AI 写代码能力足够强，**很多时候描述到位比抠细节效果更好**。

## 三、2026 最新爆火：Loop Engineering（循环工程）

> 这是 2026 年年中刚刚火起来的概念，被称为 AI 工程的下一个阶段，也是目前技术圈讨论最多的新名词。

### 1. 什么是 Loop Engineering？

**大白话：你别再一条一条给 AI 发提示词了，退到外面设计一个自动循环，让循环替你驱动 AI 干活。**

### 2. 它解决了什么痛点？

很多人用 AI 写代码、做项目是这样的：

```text
你写提示词 → AI 输出结果
你运行 / 检查 → 发现有问题
把错误粘回去 → AI 修改
再检查 → 又有新问题
来回复制粘贴，无限循环……
```

你会发现：**你自己变成了循环里的那个齿轮，全程人肉驱动 AI**。名义上是 AI 帮你干活，实际上你在给 AI 打下手。

### 3. Loop Engineering 怎么做？

**人不再坐在循环里一步步发指令，而是退到循环外面：**

- 设定好最终目标、验收标准
- 设计一套自动循环规则：做错了怎么改、遇到问题怎么处理、什么时候算完成
- 写一个自动闭环系统，让循环驱动 Agent 一步步跑
- 人只负责设定目标和验收最终结果，不参与中间每一步

## 四、一张表看懂 AI 工程演进脉络

| 阶段 | 核心能力 | 人的角色 |
|------|----------|----------|
| LLM 时代 | AI 会说话 | 提问者 |
| Prompt 时代 | 人会问对问题 | 提示词工程师 |
| RAG 时代 | AI 能用私有资料 | 知识库搭建者 |
| Agent 时代 | AI 会自己用工具 | 任务下达者 |
| **Loop 时代** | **AI 能自动闭环迭代** | **系统设计者** |

> 总结成一句话：**没有 AI 你自己干活，Prompt 时代你说一句 AI 动一下，Agent 时代你给目标 AI 自己跑全程，Loop 时代你搭一条自动化流水线，AI 在流水线上自己跑、自己测、自己改，跑通了自动停下。**

## 五、给新手的一点建议

> 不用死记硬背，**知道每个名词在解决什么问题就行**。这些名词本质都是工具，理解用途比背定义有用得多。

**1. 别追名词焦虑。** 很多新名词换汤不换药，底层逻辑没变，只是工程范式在升级。

**2. 按顺序学。** 先搞懂 LLM、Prompt、RAG，再看 Agent、MCP，最后了解 Loop Engineering，**足够应对绝大多数 AI 应用开发场景**。

**3. Loop Engineering 很新，但不用慌。** 它是工程思路的升级，不是凭空冒出来的黑科技，**理解理念比急于上手更重要**。
